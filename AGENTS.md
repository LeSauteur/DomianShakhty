# Обязательный порядок работы и публикации

Эти правила действуют для всего репозитория. Перед любыми изменениями прочитай этот файл полностью.

## Канонический проект

- Рабочий репозиторий: `https://github.com/LeSauteur/DomianShakhty.git`.
- Канонический remote: `origin`.
- Публичный PRELAUNCH: `https://lesauteur.github.io/DomianShakhty/`.
- Публикация уже настроена в `.github/workflows/pages.yml`: push/merge в `main` автоматически собирает `dist` и разворачивает GitHub Pages.
- Проверка pull request настроена в `.github/workflows/qa.yml`.

## Перед началом работы

1. Выполни `git status --short`, `git branch --show-current` и `git remote -v`.
2. Сохрани все чужие и незавершённые изменения. Не перезаписывай и не удаляй их.
3. Если рабочая ветка или dirty worktree принадлежат другой активной задаче, не переключай ветку и не коммить поверх неё: сначала согласуй продолжение или используй отдельный безопасный worktree.
4. Для новой работы используй ветку с префиксом `codex/` от актуального `origin/main`.

## Обязательная проверка

Перед push запусти:

```powershell
npm ci
npm run qa
```

Если менялись крупные изображения или критический layout, дополнительно проверь desktop и mobile в браузере: загрузку нужного `currentSrc`, отсутствие горизонтального переполнения и ошибок консоли.

Не обходи упавший тест. Исправь причину и повтори полный `npm run qa`.

## Единственный штатный порядок публикации

```powershell
git push -u origin <ветка>
gh pr create --base main --head <ветка>
gh pr checks <PR> --watch --interval 10
gh pr merge <PR> --merge --delete-branch
git checkout main
git pull --ff-only origin main
gh run list --limit 5
gh run watch <ID_RUN_DEPLOY> --exit-status
```

После успешного workflow открой `https://lesauteur.github.io/DomianShakhty/` с cache-bust query, проверь затронутые страницы на desktop и mobile и только после этого сообщай о завершении.

## Запрещённые обходные пути

- Не используй Sites для публикации этого репозитория.
- Не создавай `.openai/hosting.json` и не меняй hosting-конфигурацию, если пользователь прямо этого не попросил.
- Не отправляй проект на `git.chatgpt-team.site` или другие временные Git-серверы.
- Не передавай ручные `Authorization`-заголовки и токены в командах Git.
- Не меняй `origin` и не добавляй новый deployment remote.
- Не запускай интерактивную Git-авторизацию. Если обычный `git push origin` или `gh` требует входа, остановись и сообщи точную ошибку.
- Не завершай процессы `git` вслепую. Сначала установи, какой процесс завис и кому он принадлежит.
- Не пушь напрямую в `main`: используй PR и дождись зелёного QA.

Если публикация не прошла, GitHub Pages обычно ни при чём: сначала открой упавший шаг через `gh run view <ID> --log-failed`, исправь конкретный тест и повтори тот же штатный процесс.
